# ADR 0010：本地交互式任务工作台

## 状态

已接受，随 `v0.10.0` 实施。

## 背景

`v0.7.0` 的 Web 工作台只能读取实验 Artifact，真实项目任务仍需通过多段 CLI 命令完成。`v0.9.0` 又增加了“规划—人工审批—执行”两阶段流程。虽然安全边界清晰，但用户无法在同一界面创建任务、检查验收契约、观察运行状态并查看最终补丁，网页中的 Fake Benchmark 也容易被误解为当前可操作的真实任务。

## 决策

1. Web 默认进入“真实任务”工作面，原有 Benchmark 与实验视图保留在“实验分析”页签。
2. 后端增加单 worker 任务队列。一个 Job 依次经历验收规划、等待审批、执行和最终验收，避免多个本地 Agent 同时争用 CPU、模型预算和 Git worktree。
3. 任务创建请求必须显式确认代码可发送到所选 Provider。API Key 只从启动服务的进程环境读取，前端没有 Key 输入框，任务快照也不保存凭据。
4. 验收契约完整展示条件、保持行为、边界情况、结构化用例、允许路径、验证命令、证据文件和 SHA-256。批准请求必须携带用户刚刚审阅的契约哈希；文件变化时拒绝执行。
5. 后台 Trace 通过受限监听器转换为浏览器安全事件，只公开阶段、工具名称、策略结果、短摘要、耗时和 Token 使用，不转发工具原始参数、完整文件内容或私有推理。
6. 浏览器使用 SSE 获取实时事件。Job 快照以原子替换方式写入 `artifacts/jobs/`，页面刷新可以恢复；服务重启后仍处于活动状态的旧 Job 明确终止，不冒充仍在运行。
7. 取消采用协作式语义：尚未运行的 Future 直接取消；Agent 在模型响应之间和工具调用之间检查取消标记；Verifier 轮询子进程并在取消时终止当前验证。已经产生的隔离 worktree 和审计 Artifact 保留。
8. 写接口拒绝非回环浏览器 Origin，CORS 仅允许本机来源；`amor web` 拒绝监听非回环地址。缺少 Origin 的本机 CLI 请求仍可使用 API。
9. 运行成功后只展示和保留补丁，不自动提交、推送、创建 PR 或修改用户原工作副本。

## 理由

这一设计把 AMOR 已有的可信执行证据链变成可直接体验的产品流程，同时没有扩大 Agent 权限。单队列和持久快照比引入数据库、分布式 worker 或多用户认证更符合本地 MVP；SSE 足以表达单向事件流，也比 WebSocket 更容易审计和恢复。

## 限制与后续

- 模型 HTTP 请求开始后不能立即强制中断，只能在请求返回或超时后完成取消。
- 任务记录可以跨页面刷新恢复，但进程重启不恢复执行中的 Python 线程。
- 本地服务仍会执行用户批准的目标项目命令，不是容器安全沙箱。
- 当时没有人工编辑契约或直接回答规划问题的能力；该限制已由 [ADR 0011](./0011-contract-revision-loop.md) 的不可变契约修订链解决。
- 公网版本必须先增加每任务容器、无网络执行、资源限额、预置仓库、身份认证和请求限流；在这些条件完成前不得绑定公开地址。
