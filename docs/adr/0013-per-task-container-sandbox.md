# ADR 0013：每任务容器命令沙箱

## 状态

已接受，随 `v0.13.0` 实施。

## 背景

Git worktree、路径策略、命令白名单和子进程超时能防止误操作，但目标项目的测试代码仍与 AMOR 服务共享宿主机内核环境、网络和可见进程。结构化验收与隐藏测试也会导入目标代码，因此仅将 Agent 主循环放入隔离目录不足以运行不可信代码。

## 决策

- `amor run` 和 Web 真实任务默认选择 Docker；Benchmark 与历史任务保持显式的宿主机兼容行为，避免悄然改变已有实验基线。
- 可见验证、独立 Verifier、结构化外部验收和隐藏测试复用同一个执行抽象，不能出现“Agent 在容器、Verifier 在宿主机”的边界分裂。
- 每条目标命令使用一次性容器，固定 `--network none`、只读根文件系统、移除 Linux capabilities、启用 `no-new-privileges`，且不挂载 Docker socket、Provider Key 或用户主目录。
- 只把隔离 worktree 以可写方式挂载到 `/workspace`。验收契约、可信运行器和隐藏测试必须由 Verifier 显式声明，并以只读挂载提供；验证命令中的其他工作区外绝对路径一律拒绝。
- 默认限制 1 CPU、512 MB 内存、128 个进程、64 MB `tmpfs`、256 MB 工作区增长和单命令时间。工作区增长由宿主监视器检测并终止超限容器。
- 用户取消或命令超时时，通过唯一容器名执行 `docker kill`，随后回收 `docker run --rm` 控制进程。
- Docker 引擎未运行或基础镜像本地不存在时失败关闭。运行期使用 `--pull never`，避免沙箱启动隐式联网或执行供应链下载。
- `host` 仅作为用户显式选择的兼容模式，并在界面中标记其隔离能力较弱。

## 安全性质

容器内目标代码无法通过普通网络访问外部服务，也不会继承 AMOR 进程环境变量。独立验收资料保持工作区外、只读且只由 Verifier 挂载。容器仍可修改隔离 worktree，这是 Agent 运行测试和生成临时文件所必需的；最终补丁继续接受允许路径与指纹检查。

## 限制

- Docker 不是虚拟机边界，安全性仍依赖 Docker Desktop/Engine 与宿主内核。
- 当前默认镜像是 Python 3.12；Node、Java 等项目需要未来的受控镜像目录和镜像摘要锁定。
- 工作区增长限制是高频监视和强制终止，不是文件系统级原子配额，短时间内可能略微越过阈值。
- Docker 沙箱不等于公网多租户就绪。任意仓库导入、身份认证、限流、预置镜像治理和服务端路径隐藏仍未完成。
- Git、文件读取、代码搜索和补丁应用仍由宿主 AMOR 进程执行，但只能作用于隔离 worktree，并继续经过路径与敏感文件策略。
