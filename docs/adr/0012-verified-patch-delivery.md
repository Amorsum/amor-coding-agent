# ADR 0012：已验收补丁通过独立 worktree 安全交付

## 状态

已接受，随 `v0.12.0` 实施。

## 背景

此前 AMOR 的成功补丁只保存在运行 Artifact 的 detached worktree 中。用户可以查看 Diff，却需要手工复制或应用，容易选错任务、契约或补丁版本。直接在用户当前工作副本中切分支并应用补丁又会改变用户现场，使失败恢复和并发任务变得不可控。

## 决策

1. 成功运行保存完整二进制 Git Patch 和 SHA-256。生成补丁时使用临时 Git Index，因此新增、修改、删除、重命名和二进制文件都进入交付证据，同时不改变 Agent worktree 的真实 Index。
2. 只有 Agent 最终状态为 `SUCCEEDED` 且 Verifier 通过时可以发起交付。请求必须携带最新契约哈希、补丁哈希、一个尚不存在的本地分支名，以及显式确认。
3. 交付前和工作线程开始时都检查目标仓库工作区干净、HEAD 与契约基准一致、补丁内容与保存的 SHA-256 一致。任何漂移都终止交付。
4. 系统通过 `git worktree add -b` 从基准提交创建独立交付 worktree，不切换或修改用户原仓库当前分支。补丁通过标准输入传给 `git apply --binary`，不经过 shell。
5. 应用后重新生成完整补丁并比较 SHA-256，然后用相同任务、批准命令和结构化验收契约重新运行独立 Verifier。只有再次通过才能进入成功状态。
6. 用户可以选择在交付 worktree 中生成本地 commit。提交使用目标仓库已有的 `user.name` 和 `user.email`；缺少身份时提前拒绝。关闭提交时，已验证修改保留在交付 worktree 中供人工检查。
7. 系统不推送远端、不创建 PR、不删除失败现场。每次尝试独立保存请求、结果、Verifier 证据、分支、commit SHA 和 Artifact 路径；失败后必须换用尚不存在的分支名重试。
8. 交付进入同一个单 worker 队列并支持协作式取消。取消或交付失败不推翻原始 Agent 验收结果。

## 理由

独立交付 worktree 把“可审阅的成功补丁”转换成“可继续开发的本地分支”，同时不侵入用户当前工作状态。契约、补丁和基准三重绑定防止把正确补丁交付到错误代码版本；落地后二次验收能够发现换行、文件模式、环境或应用过程造成的偏差。

## 限制与后续

- 本地分支和 worktree 会持续占用磁盘，当前不自动清理；用户确认不再需要后可使用标准 Git worktree 命令处理。
- 未请求 commit 时，分支引用仍指向基准提交，修改只存在于对应交付 worktree，适合人工检查而非直接切换使用。
- 当前仍在宿主机执行验证命令。对不可信仓库开放之前，必须完成每任务容器、断网执行和资源限制。
- 本版不自动推送或创建 GitHub PR；远端协作属于后续独立审批边界。
