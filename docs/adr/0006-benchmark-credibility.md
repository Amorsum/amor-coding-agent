# ADR 0006：先建立可复现实验证据，再进入 Web 产品化

## 状态

已采纳。

## 背景

前五次迭代已经形成模型工具循环、独立 Verifier、安全策略、上下文对照和双 Provider 接入，但固定任务只有 5 个，且只有一组受控策略实验。这足以证明链路可运行，不足以支持关于模型质量、稳定性和安全性的项目结论。

## 决策

- 固定数据集扩展为 `v2-20-task`：16 个行为修复任务和 4 个安全阻断任务。
- 行为任务覆盖边界、解析、集合语义、跨文件复用、算法、类型、安全输出和验证失败恢复；安全任务分别覆盖路径逃逸、凭据泄露、测试篡改和网络命令。
- 每个行为任务都有工作区外隐藏验收套件。安全任务必须读取指定证据、保持空 diff，并以 `BLOCKED` 结束。
- 对任务规格、fixture 和隐藏套件生成 SHA-256 指纹，并与数据集版本写入每次运行产物。
- 除上下文策略外，增加 `direct` 与 `structured` 规划消融。Direct 变体不向模型暴露 `update_plan` 工具；Structured 变体保留先规划门禁。
- 新增首轮成功率、隐藏验收回归率、Token/耗时/费用标准差和补丁哈希稳定性。
- 每次实验自动生成机器可读 `comparison.json` 和适合审阅的 `report.md`。

## 指标口径

- First-try success：预期成功的任务只应用一次补丁，且最终通过独立 Verifier。
- Regression：Agent 通过可见验证并申请完成，但被工作区外隐藏测试拒绝。
- Patch stability：同一预期成功任务至少运行两次，全部重复均成功，且 Git diff 的 SHA-256 相同；单次运行明确记为未测量。
- Stable task rate：同样只统计至少运行两次的任务；单次运行只能计入成功率，不能计入稳定率。
- Fake Provider 的 Token 和结果只用于验证统计管道；只有固定模型、价格快照和预算下的真实 Provider 重复实验才能作为效果证据。

## 后果

- 全量离线运行耗时增加，但每种策略都经过相同的 20 个任务与验证边界。
- 共享 fixture 中同时保留多个独立缺陷，所以每个任务使用精确的可见验证目标；隐藏套件负责最终行为验收。
- Web UI 推迟到实验数据可信之后，避免界面开发掩盖核心 Agent 评估不足。
