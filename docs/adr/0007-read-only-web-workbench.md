# ADR 0007：先以只读 Artifact 工作台进入 Web 产品化

## 状态

已采纳。

## 背景

前六次迭代已经能够生成 Benchmark 汇总、受控实验、任务报告、JSONL 轨迹和 Git Diff，但主要入口仍是 CLI 和文件系统。直接在网页开放仓库路径、命令或模型运行会扩大本地任意代码执行风险，也会把任务创建、进程管理和审批等问题一次性引入首个 Web 版本。

## 决策

- `v0.7.0` 只展示既有 Artifact，不从网页创建或执行 Agent 任务。
- FastAPI 默认监听 `127.0.0.1:8765`，并同源托管构建后的静态工作台。
- API 只接受服务器生成的 16 位实验 ID，不接受文件路径。
- Artifact 中记录的 `summary_path`、`report_path`、`trace_path` 和 `workspace_path` 不作为读取依据，也不返回给前端。
- 任务详情只能通过实验清单中已经存在的 strategy、task ID 和 attempt 组合读取。
- 单文件读取设置大小上限，格式错误的 Artifact 与不存在的 Artifact 分别返回明确错误。
- 前端使用 Vite、React 和少量 shadcn 组件，展示实验列表、策略对比、任务表、Verifier 检查、轨迹与 Diff。
- Fake Provider 在页面中显式标记为“非模型质量证据”。

## 后果

- 用户构建前端后，只需运行 `amor web` 即可在本机查看已有结果。
- 首个 Web 版本没有任务提交、任意仓库访问、任意命令、账号系统或远程部署能力。
- 后续加入实时 Agent 运行时，需要单独设计任务输入校验、审批、取消、事件流与进程隔离，不能复用只读接口绕过安全边界。
