# ADR 0004：上下文策略必须在相同验证边界内对照

## 状态

已采纳。

## 决策

第四迭代增加 `broad` 与 `search-first` 两种上下文策略，并通过 `amor experiment` 在相同任务、模型、工具、Verifier、上下文预算和重复次数下运行两组 Benchmark。

每条进入模型上下文的工具结果都会产生 `context_evidence` 事件，记录来源工具、路径、进入原因、读取行数、请求与保留字符数、是否重复、是否为空搜索以及是否发生压缩。跨轮上下文使用统一字符预算；超出预算的输出保留首尾和工具摘要。

任务、验收条件、允许写入范围和剩余 Token 预算属于稳定任务胶囊，每轮都进入 instructions。这样既满足上下文压缩时不可丢失核心约束，也符合 Responses API 在使用 `previous_response_id` 时不会自动继承上一轮 instructions 的接口语义。

真实模型的每次输出和累计 Token 都设有硬上限。费用只依据运行时显式传入并写入配置的每百万 Token 单价估算，不在代码中内置会过期的价格。

## 后果

- Fake Provider 可以稳定验证实验和指标管道，但其结果不能代表真实模型质量。
- `comparison.json` 直接给出成功率差值，以及输入 Token、工具调用、保留上下文、读取文件和可选费用的减少率。
- 真实结论必须在用户指定的同一模型上重复运行，并保留当时的价格快照。
- 字符预算是可审计的近似上下文预算；模型 Provider 返回的 Token usage 仍是实际效率和费用统计依据。
