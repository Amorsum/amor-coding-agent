# ADR 0017：只读项目展示与完整仓库入口

## 状态

已采纳，适用于 `v0.17.0`。

## 背景

`v0.15.0` 将 `amor.amorsum.top` 限制为静态脱敏实验页面，避免把持有本地路径、Provider Key、Git 权限和 Docker 控制能力的工作台直接暴露到公网。该边界足够安全，但单份实验报告没有清楚告诉访客完整产品在哪里，也容易让人误以为静态报告就是全部功能。

曾考虑让访客在公网输入自己的 Provider Key 并运行预置任务。BYOK 可以转移模型费用，但仍会引入凭据传输、服务器资源滥用、恶意仓库、隔离逃逸和多租户运维风险；它也要求访客信任演示站处理真实密钥。对于当前以项目展示和简历投递为目标的阶段，这些成本高于收益。

## 决策

- `amor.amorsum.top` 长期保持静态、只读，不部署 FastAPI、本地任务 API、Docker 控制面或模型 Provider 代理。
- 真实仓库分析、Agent 执行、Verifier、补丁交付和 GitHub Draft PR 发布继续只在用户本机运行。
- 每个新导出的公开快照在首屏和页脚显示固定的完整项目仓库入口：`https://github.com/Amorsum/amor-coding-agent`。
- 快照数据增加项目名称、版本、仓库地址、公开模式和完整工作台位置。这些字段进入规范化内容和快照 ID，因而受到现有 SHA-256 清单保护。
- 页面明确说明不接收 API Key、不上传仓库、不执行代码，避免把展示功能描述成在线 Coding Agent。
- 页面仍不包含 JavaScript、表单、外部图片或外部字体。固定仓库链接仅用于顶层导航，并使用新标签页及 `noopener noreferrer`。
- `.openai/hosting.json` 继续只发布 `out/`，暂存目录仍严格限制为 `index.html`、`showcase.json` 和 `manifest.json`。

## 结果

访客可以从实验证据直接进入完整源码、架构决策和本地运行文档，同时公网攻击面仍接近纯静态文件。代价是招聘方无法在网页中直接运行真实 Agent，但无需提供密钥，也不会消耗项目维护者的模型或执行资源。

如果未来产品目标从作品展示变为正式 SaaS，必须单独设计身份认证、密钥生命周期、多租户隔离、远程执行节点、资源配额、滥用防护和数据清理；该变化不能通过放宽当前静态站配置完成。
