# ADR 0002：用 Responses API 函数调用接入本地仓库

## 状态

已接受。

## 决策

第二迭代增加 `amor profile` 和 `amor run`：

- 只接受已提交且工作区干净的本地 Git 仓库。
- 从目标仓库 `HEAD` 创建 detached worktree。
- 用户必须显式给出允许修改的 glob 和验证命令参数数组。
- 模型 Provider 使用 Responses API 函数调用，并通过 `previous_response_id` 延续任务。
- 每个函数调用输出用原始 `call_id` 回传。
- 每轮重新提供系统指令，避免依赖前一响应隐式继承指令。
- 模型只能请求验证；最终成功状态仍由独立 Verifier 写入。

## 安全与隐私

仓库内容、注释和测试输出均被视为不可信数据。所有模型工具调用继续经过原有路径策略、命令白名单和输出限制。CLI 要求 `--confirm-send-code`，因为相关源码和测试输出会离开本机并发送给用户配置的模型服务。

API Key 只从进程环境读取，不写入任务、轨迹或报告。

## 当前限制

- 任意本地任务没有 Benchmark 隐藏测试，Verifier 只能证明修改范围、语法和用户提供的验证命令通过，不能单独证明自然语言语义完全满足。
- 当前 API 会话使用服务端响应状态延续。
- 测试仍运行在本机受控子进程中，而非无网络容器。
- 成功补丁不会自动应用、提交或推送到原仓库。
