# ADR 0009：独立验收规划与结构化外部用例

## 状态

已接受，随 `v0.9.0` 实施。

## 背景

`v0.8.0` 已将最终验收从执行 Agent 的自我判断中分离，但真实项目的验收条件和可见验证命令仍主要由用户提供。用户通常只描述期望行为，无法完整枚举回归、边界和异常情况。若让执行 Agent 自己设计唯一的测试，它可能只验证自己选择的实现路径。

## 决策

在执行任务前增加独立的只读验收规划阶段：

1. 规划器使用独立 Provider 会话，只获得列表、搜索和读文件工具。
2. 仓库文件被视为不可信数据；规划器不能运行命令、编辑文件、联网或请求凭据。
3. 输出包含验收条件、必须保持的行为、边界情况、待确认问题和 Python 结构化函数用例。
4. 用例只能引用规划器真实读取过的项目模块，参数和期望值必须是 JSON，预期类型仅为等值或内置异常。
5. 规划文件绑定 Git 基准提交并通过规范 JSON 计算 SHA-256。有未解决问题时状态为 `NEEDS_INPUT`，不得执行。
6. 用户阅读中文报告后必须显式提供 `--approve-contract`。
7. 执行 Agent 获得已冻结的任务条件，但外部用例文件保留在 Agent 工作区之外。Verifier 由 AMOR 自身的固定解释器执行结构化数据，不执行模型生成的任意测试代码。
8. 契约验收失败时，失败摘要进入 `v0.8.0` 的有限修复闭环。最终结果仍不自动合并、提交或部署。

## 理由

独立会话降低执行 Agent 同时出题和作答的偏差。冻结、绑定基准和用户审批防止验收标准在实现过程中漂移。结构化用例表达力低于任意测试源码，但它能显著减少模型产生代码被直接执行的风险，适合当前 Python-first 迭代。

## 后果与限制

- 规划和执行会各消耗一次模型 API 用量。
- 规划器是受限的辅助者，不是绝对正确的验收权威；用户审批仍是必要边界。
- 当前仅支持 Python 仓库中可导入的同步函数/可调用对象，不直接覆盖 HTTP、数据库、浏览器、异步流程或复杂环境搭建。
- 验收运行仍会导入并执行目标仓库中的可调用对象，因此本机子进程隔离不等同于容器安全沙箱，不应对恶意仓库使用。
- 后续版本可增加多语言适配器、属性测试、契约可视化审批和更强的进程/容器隔离。
