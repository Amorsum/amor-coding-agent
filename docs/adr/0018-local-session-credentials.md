# ADR 0018：本地会话凭据与可操作就绪检查

## 状态

已采纳，适用于 `v0.18.0`。

## 背景

本地工作台已经具备任务规划、契约审批、Agent 执行、Verifier 和补丁交付接口，但 Provider Key 只能在启动终端通过环境变量设置。首次使用者打开页面时只能看到按钮不可用和“服务端 Key 未配置”，容易把完整工作台误认为只读页面，也无法从界面判断还缺少哪些条件。

把 Key 保存到浏览器、配置文件或任务 Artifact 会扩大泄露面；把本地任务 API 开放到公网则会同时暴露仓库路径、执行资源和 Git 权限。这些都不符合当前单用户本地工具的边界。

## 决策

- 本地工作台提供 OpenAI Responses 与 DeepSeek Responses 的 API Key 输入和清除操作。
- 页面提交的 Key 只保存在当前 FastAPI 服务进程的内存字典中；不进入浏览器持久化存储、任务请求、JobSnapshot、轨迹、日志或 Artifact。
- 服务关闭时清空会话凭据。Python 字符串无法承诺密码学意义上的内存擦除，因此这里只保证引用生命周期和不持久化，不宣称安全擦除。
- 环境变量继续受支持。会话 Key 优先于环境变量；清除会话 Key 后自动回退到环境变量。
- Runtime API 只返回每个 Provider 是否就绪及来源 `environment`、`session` 或 `missing`，永不返回 Key 或任何可用于恢复 Key 的值。
- 凭据写入和清除接口与其他修改接口一样只接受回环 Origin；服务本身仍只能监听回环地址。
- 任务创建页列出凭据、仓库、任务描述、模型 ID、发送确认和 Docker 状态，并给出具体阻塞原因。
- “创建任务并生成验收方案”表示创建真实任务记录并先运行只读规划；代码修改仍必须等待用户审阅并批准冻结的验收契约。
- 公网站点继续发布静态 `out/`，不接入凭据接口或任务执行 API。

## 结果

用户无需重启服务或操作 PowerShell 环境变量即可开始真实任务，页面也能解释按钮为何不可用。代价是服务重启后需要重新输入会话 Key，这是避免磁盘持久化的有意取舍。环境变量适合固定个人开发环境，会话 Key 适合演示和临时使用。
