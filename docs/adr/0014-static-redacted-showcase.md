# ADR 0014：静态脱敏导出与公开展示模式

## 状态

已接受，随 `v0.14.0` 实施。

## 背景

本地工作台同时持有仓库路径、任务指令、代码 Diff、模型轨迹和执行入口，不能直接部署到公网。简历或项目展示真正需要的是可复现实验结论，而不是这些高风险原始资料。手工截图又缺少数据来源、可复现性指纹和完整性证明。

## 决策

- 公开展示不是给现有工作台增加公网监听，而是从一个已列出的实验重新构造独立静态快照。
- 导出只接受 ArtifactStore 生成的 16 位实验 ID，不接受调用方提供的路径。
- 采用字段白名单，只保留实验配置摘要、策略聚合指标、任务 ID、任务状态、Verifier 布尔结果和资源统计。
- 明确排除任务指令、验收条件与结构化用例、代码与 Git Diff、工具轨迹与模型输出、补丁哈希、报告路径、工作区路径和环境变量。
- 导出需要用户显式确认。相同标题与相同公开数据生成相同内容 ID；源数据变化会产生新目录，不覆盖旧快照。
- 每次输出 `index.html`、`showcase.json` 和 `manifest.json`。清单记录两个公开文件的 SHA-256，读取历史快照时重新验证。
- HTML 由服务端转义并直接渲染，不包含 JavaScript、表单、外部字体、外部图片或网络请求；CSP 默认拒绝所有资源，仅允许内联样式。
- Fake Provider 快照必须醒目标明“非模型质量证据”。
- 本地 API 可创建和列出快照，并通过 `/showcases/<id>/` 预览；创建端点继续要求 loopback Origin。

## 后果

用户可以把单个快照目录交给纯静态托管，而无需暴露 AMOR 后端、Provider Key、本地路径或任意代码执行能力。内容哈希既能标识版本，也能在展示文件被改写时阻止系统把它当作原快照读取。

## 限制

- 当前只导出策略实验，不导出真实项目任务详情；后者更容易包含私有业务信息。
- 任务 ID 与模型 ID属于用户确认公开的实验元数据；需要匿名展示时应在未来增加可选别名映射。
- 清单提供完整性校验，不提供发布者身份签名。
- 本版不自动上传、部署或绑定域名。正式发布必须只部署快照目录，不能部署本地任务 API。
